# 2026-11-28 밸런스 시뮬레이션 (F8)

`npm run sim` (src/sim/). 봇(src/sim/bot.ts)이 "무난하게 하는 플레이어"처럼 판을 돌린다:
다치면 쉬고, 의뢰를 맡아 그쪽으로 가고, 잡동사니는 팔고, 더 좋은 장비는 낀다. 최선의 플레이가 아니라 숫자를 맞출 기준선이다.
판 수는 `SIM_RUNS`, 걸음 수는 `SIM_STEPS` 로 바꾼다 (PowerShell: `$env:SIM_RUNS=1000; npm run sim`).

## 목표 (docs/goals/02-foundation.md F8)
- 초반에 죽는 비율은 지금 그대로 (기준선 30걸음 안 14.5%)
- 레벨이 오를수록 조금씩 쉬워짐
- 골드를 쓸 곳은 따로 만들지 않고 가격·보상으로 맞춘다

## 기준선 (조정 전, 200판 × 600걸음)

| 지표 | 값 |
|---|---|
| 30걸음 안에 처음 죽은 판 | 14.5% |
| 판당 번 골드 / 쓴 골드 | 9730 / 1237 |
| 600걸음 골드 (중간값) | 8974 |
| 600걸음 레벨 (중간값) | 14 |
| 짐이 80%를 넘은 걸음 비율 | 57.0% |

레벨 구간별 100걸음당 죽음: 1~2 레벨 0.39 → 3~4 0.03 → 5~6 0.01 → 7~9 0.02 → 10+ 0.01
(레벨 3부터 한 번에 10배 넘게 쉬워졌다. "조금씩"이 아니다)

## 바꾼 숫자 (모두 [임시값])

| 무엇 | 전 | 후 | 까닭 |
|---|---|---|---|
| 적 레벨 배율 (core/battle.ts ENEMY_LEVEL) | 레벨당 +12% | 레벨 6까지 +20%, 그 뒤로 +8% | 고르게 +20%면 고레벨이 오히려 위험해졌다 (10+ 레벨 1.38). 초반은 빨리 따라오고 후반은 천천히 |
| 적이 주는 골드 | 레벨을 따라 오름 | 오르지 않음 | 골드가 너무 남았다 |
| 우두머리 골드 | 10~25 | 6~12 | 우두머리·궤짝이 가장 큰 수입이었다 |
| 궤짝 골드 (core/dungeon.ts) | 20~35 | 6~14 | 같은 까닭 |
| 의뢰 보상 (core/quests.ts QUEST_GOLD) | 처치 8+6×수, 던전 45, 레벨당 +10% | 처치 5+4×수, 던전 30, 레벨당 +5% | 같은 까닭 |
| 팔 때 받는 값 (흥정 시작값 / 최대) | 50% / 75% | 35% / 60% | 잡동사니 판매가 세 번째로 큰 수입이었다 |
| 여관비 | 10 | 10 + 레벨당 3 | 가격으로 쓰는 곳을 늘린다 |
| 걸음마다 차는 마력 | 1 | 2 | 눈요정이 던전 끝에서 마력이 말라 우두머리에게 쓰러졌다 |

## 읽는 법과 남은 것
- 초반 죽는 비율은 13.7%로 기준선(14.5%)과 비슷하게 남았다.
- 레벨 구간별 위험은 대체로 조금씩 줄어든다. 5~6 레벨이 3~4 레벨보다 약간 높은 것은 장비 등급이 바뀌기 전(레벨 4·8) 구간이라서로 보인다.
- 600걸음 골드는 8974 → 3314로 줄었지만 여전히 쌓인다. 쓸 곳을 만들지 않기로 했으므로(6a) 더 줄이면 보상이 시시해진다. 플레이해 보고 다시 본다.
- 눈요정은 30걸음 안에 죽는 판이 아직 다른 종족보다 많다 (25%, 북방인 5%). 봇이 마력이 떨어져도 던전에서 물러나지 않는 탓도 있다. 종족 성격을 바꾸는 일이라 docs/open-questions.md 에 올린다.
- 짐이 80%를 넘은 걸음이 절반쯤이다. 무게 고민이 늘 있다는 뜻이고, 너무 잦은지는 플레이해서 판단한다.
- 봇은 600걸음에 우두머리를 50번쯤 잡는다. 던전에 자주 들어가는 플레이어 기준이다.
